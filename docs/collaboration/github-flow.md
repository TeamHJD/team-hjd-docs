# GitHub 작업 흐름

> **중요도: 필수** · 할 일을 맡고 처음 변경을 올리기 전에 읽습니다.

## 작업 시작 전

1. Issue에서 작업의 목적과 완료 조건을 확인합니다.
2. Issue와 연결되는 Branch를 만듭니다.
3. 작은 단위로 Commit하고 원격에 Push합니다.

## 작업이 끝나면

1. Pull Request에 변경 이유와 확인 방법을 적습니다.
2. 리뷰 의견과 CI 결과를 반영합니다.
3. Merge 뒤 Issue의 완료 상태를 확인합니다.

PR 작성 기준은 [Pull Request와 리뷰](../delivery/pull-request)에서 확인합니다.
