# 팀 작업 약속

> **중요도: 필수** · 이 페이지는 팀이 합의한 실제 규칙으로 채워갈 공간입니다.

## 우리가 기록할 결정

- Branch 이름과 Commit 메시지 규칙
- PR을 요청할 수 있는 최소 기준
- 리뷰 응답 시간과 승인 기준
- Merge 방식과 배포 기준
- 막힘(Blocker)을 공유하는 채널과 시점

규칙은 통제가 아니라, 서로의 다음 행동을 예측 가능하게 만드는 약속입니다. 새 합의가 생기면 이유와 함께 이곳에 남깁니다.

## 작업을 시작하기 전

작업마다 아래 네 가지를 먼저 맞추면, 중간에 다시 확인하는 비용을 줄일 수 있습니다.

- [ ] 연결된 Issue가 있고, 작업의 목적과 완료 조건을 설명할 수 있는가?
- [ ] 다른 작업과 겹치지 않는 Branch에서 시작하는가?
- [ ] 선행 작업, 의존성, 공유가 필요한 변경이 있는가?
- [ ] 완료 뒤 무엇을 확인할지(테스트, 화면, 로그 등) 알고 있는가?

## PR을 올리기 전

PR은 단순한 Merge 요청이 아니라 변경의 맥락을 다음 사람에게 넘기는 기록입니다.

- [ ] 변경 이유와 핵심 내용을 짧게 요약했는가?
- [ ] 관련 Issue를 연결하고, 남은 작업이나 주의할 점을 적었는가?
- [ ] 파일 변경 사항을 직접 읽어 보고 불필요한 변경을 뺐는가?
- [ ] 확인한 방법과 아직 확인하지 못한 부분을 구분해 적었는가?

자세한 순서는 [PR과 리뷰](../delivery/pull-request), 자동 검증 기준은 [CI와 품질 확인](../delivery/quality-checks)을 따릅니다.

## 막혔을 때 남길 정보

도움을 요청할 때는 “안 됩니다”보다 아래 맥락을 함께 남깁니다. 상대가 같은 상황을 재현하고 다음 행동을 정하는 데 도움이 됩니다.

| 남길 내용 | 예시 |
| --- | --- |
| 기대한 결과 | “Play를 누르면 Main Scene이 로드되어야 한다.” |
| 실제 결과 | “Console에 null 예외가 발생하고 Scene 전환이 멈춘다.” |
| 시도한 것 | “참조 연결과 Console 첫 오류를 확인했다.” |
| 필요한 도움 | “EnemySpawner 초기화 순서를 함께 확인하고 싶다.” |

## 합의 변경 기록

새 규칙을 추가하거나 바꿀 때는 아래 형식으로 남깁니다. 규칙 자체뿐 아니라 **왜 바꿨는지**를 적어야 이후에도 맥락이 남습니다.

| 날짜 | 결정 | 이유 | 적용 시점 |
| --- | --- | --- | --- |
| YYYY-MM-DD | 예: PR 승인 기준 변경 | 예: 특정 유형의 누락을 줄이기 위해 | 즉시 / 다음 스프린트 |
